# No address is stored; the ZIP is a private string

`addresses.yaml` could not be guarded well enough. The main session has Bash, deny rules match a call's text, and [ADR 0003](0003-the-model-never-sees-an-address.md)'s Limits list the reads that still get past the hook. A file that does not exist cannot be read. So the data repo stores no address, street line or label (owner decision 2026-11-11, ticket 22). Only the ZIP code is kept, and the researcher lists it in that ballot's `private.yaml` as its own `private_strings` entry, quoted (`- "99999"`). Addresses and street lines are not moved into `private_strings`, because they are not stored at all, except on the personalized-ballot fallback (Consequences).

## Enforcement

- **One matcher.** A `private_strings` digit run of 4 or more digits that is not a year is already searched on its own, with the digit edge the ZIP class uses ([ADR 0005](0005-one-matcher-for-every-spelling-of-a-private-value.md), SKILL.md step 6.3). A five-digit entry is therefore refused wherever a ZIP from `addresses.yaml` is: in a fetch URL's path or query and in ZIP+4 form, in a redirect hop, in a `--ballot` path (with `use-ballot-file`), in `ballot.yaml` and `ignored_lines`, in a `tiers.yaml` `match` or `source`, and on the rendered page. It never matches inside a longer digit run, and the page's generated dates are skipped for it as they are for the ZIP class. No script change was needed. The refusal code is `private-string`, not `private-zip`.
- **The ZIP is required.** `ballot-check` fails `private.yaml zip-missing`, followed by `- list-zip`, when no `private_strings` entry is exactly five digits (owner decision 2026-11-25, PR #65 review D1, ticket 66). The county's sample ballot, preferred since ticket 62, prints no ZIP, so no `line-unaccounted` line asks for it, and without it every refusal above silently does nothing for that ballot. Only a whole entry counts: a ZIP+4 entry (`99999-0001`) would also refuse a bare `0001` everywhere, and a ZIP inside another entry (`Exampleton 99999`) is not the entry the reference asks for. The failure prints no value and writes no `ballot-view.md`, so `publish`'s ballot gate, `fetch-snapshot --archive`, `agent-bind` and `discovery-fetch --brief` refuse too.
- **Tests through the commands** pin each of those places with the ZIP held only in `private.yaml`. The fixture ballot's `private.yaml` lists its ZIP, and the golden page is unchanged.
- **The reference.** [ballot-format.md](../../../skills/research-candidates/references/ballot-format.md) tells the researcher to list each ZIP as its own entry, in quotes, with an example.
- **Rollout.** Expand, then contract: both sources work side by side first (ticket 25). Then `fetch-snapshot`, `publish` and `ballot-check` stop reading `addresses.yaml` (26, 27), the address, ZIP and label classes and the file's guards go (28), "add a ballot" replaces "add an address" in the workflow (29), and the `elections` data repo is migrated (30).

## Considered Options

- **A sandbox read deny on the file**, with the scripts that read it in `sandbox.excludedCommands` (ADR 0003). Not chosen: an excluded command runs with full access, the list matches a call's text, and `fetch-snapshot` needs a network decision, so it still needed a live test and would still guard a file holding every address.
- **Move each address and street line into `private_strings`.** Not chosen by the owner: an address that is stored still has to be guarded, in `private.yaml` instead. The personalized-ballot fallback (Consequences) is the one exception. Keeping only the ZIP stores the one value that lookup URLs and county pages most often carry on its own.
- **Keep a ZIP class, read from `private.yaml`.** Not needed: the matcher already treats a five-digit private string as the ZIP class treats a ZIP, so a second class would only add a code.

## Consequences

What is given up, once tickets 26 to 28 stop reading `addresses.yaml`:

- **Street-only matches.** A URL, excerpt or page holding the street line or the full address is no longer refused unless it also holds the ZIP or another listed entry. A `--ballot` URL whose path shows the street now passes the path check; the researcher saves such a page with `--ballot --file` instead ([ADR 0004](0004-addresses-leave-only-through-the-researcher.md)).
- **The companion body check.** It matched only addresses, street lines and labels, since county-wide documents print ZIP codes by nature, so it has nothing left to match. A personalized companion fetched without a query is the researcher's to spot and retire (ticket 27). The personalized-ballot fallback (below) lists the voter's name and street line as `private_strings` again, and a companion document, such as a pamphlet or voter guide, can hold them; `ballot-check` still does not scan companion bodies, so spotting and retiring such a companion stays the researcher's (owner decision 2026-11-25, PR #65 review D4).
- **Labels.** There is nothing to label. The session names a ballot by its ballot id ([ADR 0011](0011-ballot-ids-say-no-more-than-the-county.md)).

Other effects:

- **Scope.** `addresses.yaml` is one file for the family, so every ballot's checks refused every address's ZIP. `private_strings` are listed per ballot, but they are read for the whole family wherever a ZIP from `addresses.yaml` was: `fetch-snapshot`'s URL refusals (a plain fetch, each redirect hop, the `--ballot` path and the `--file` origin), the `tiers.yaml` check and the page scan read every ballot's entries (ticket 26), and so do `ballot-check`'s `ballot.yaml` and `ignored_lines` scans (ticket 27). The owner confirmed this family-wide scope for both (owner decision 2026-11-14). Another ballot's ZIP in this ballot's fetch URL is therefore still refused, and so is another ballot's township or precinct name, which a per-ballot list would have let through. The cost is recall: another ballot's short or year-shaped entry, such as `"12"` or `"2024"`, now refuses ordinary URLs in every ballot, and a refused fetch is not written to `unfetchable.md`, so the source is lost silently. `ballot-check` pays the same cost: a `ballot.yaml` line or `ignored_lines` entry holding another ballot's entry fails, since discovery sends `jurisdiction` and `search_terms` to web searches ([ADR 0010](0010-search-and-fetch-inputs-hold-no-private-text.md)), so the researcher may have to reword a field over a family member's entry.
- **Quoting.** YAML reads an unquoted `02134` as the number 2134. `ballot-check` and every script that loads `private.yaml` fail `private-invalid`, so a missing quote fails closed and never drops a leading zero.
- **Reports.** A ZIP is reported as `private-string`, like any other entry, so a report no longer tells a ZIP from another entry's digit run (Rule 5 names only the class). `fetch-snapshot`, the `tiers.yaml` check and `publish`'s render and page scan read `private.yaml` alone (ticket 26), and so does `ballot-check` (ticket 27): its scans report `private-string` and `private-title` only, and a companion's body is no longer scanned. `ballot-check` fails `addresses-leftover` while an `addresses.yaml` is still at the project root, located by the file alone and never opening it, so `publish`'s ballot gate, `fetch-snapshot --archive`, `agent-bind` and `discovery-fetch --brief` refuse too, and a file whose guards ticket 28 removes cannot linger unnoticed.
- **History.** A data repo's history may still hold a deleted `addresses.yaml`, so `data-repo-gitattributes` keeps its `-diff` line, which the setup check does not require: a plain `git log -p`, `git show <commit>` or `git grep` prints no line of it. `git show <rev>:addresses.yaml`, `git cat-file` and `git log -p --text` are not refused, since session-guard no longer names the file, so ticket 30's choice about the history decides whether they stay open.
- **A personalized sample ballot** is the exception to "not stored at all", confirmed as the fallback (owner decision 2026-11-14, ticket 62). SKILL.md step 2 asks first for the county's non-personalized sample ballot for the precinct or ballot style, which prints no voter name or address, and uses a personalized one only when neither the county nor the state publishes a non-personalized one. The voter name and address it prints are already stored, in its snapshot under `sources/_ballot/`, so the researcher lists them as `private_strings` parts in that ballot's `private.yaml` (the name, the house number with its street, never alone, and the city only when it is narrower than the county, since each entry is refused family-wide; SKILL.md step 3): `ballot-check` can then account for the line, which `ignored_lines` cannot hold once it contains the ZIP, and `publish` and `fetch-snapshot` refuse them.
- **A ballot with no US ZIP**, such as a family member's abroad, cannot pass `ballot-check`: it would need an exemption, which is not built (ticket 66).
- `private.yaml` still holds private text, so its guards stay ([ADR 0003](0003-the-model-never-sees-an-address.md)).
