# Ballot format

`<ballot-id>/ballot.yaml` is typed by the researcher from the saved official sample ballot. The model never supplies contests, candidates, counts or `not_researched`.

```yaml
election: 2026-general
state: XX                # two-letter state code, from the step 2 district lookup
county: Exampleton County   # the county the step 2 district lookup printed
slug: k3x9qa            # from the step 3 command, never typed or invented
contest_count: 3        # contests the researcher counted on the official ballot
contests:
  - id: us-house-07
    type: candidate
    jurisdiction: XX congressional district 7   # state and district the office covers
    office_type: federal           # federal | state | local | judicial; sets the Positions issues (sections.md)
    title: Representative in Congress, 7th District   # exactly as printed
    printed_count: 2    # candidate lines counted on the official ballot (0 when all are certified write-ins)
    vote_for: 1         # seats to fill, from the printed "Vote for" line
    not_researched: [Record in public office]   # optional: sections left for later, or all
    candidates:
      - id: jane-example            # directory name under sources/<contest>/
        name: Jane Example          # exactly as printed
        party: Example Party        # exactly as printed
        status: on_ballot           # on_ballot | withdrawn_still_printed | certified_write_in
      - id: john-sample
        name: John Sample
        party: SAM                  # exactly as printed, here an abbreviation
        party_name: Sample Party    # the full name, from an official source that spells it out
        status: on_ballot
  - id: supreme-court-retention-a
    type: retention
    jurisdiction: XX supreme court
    office_type: judicial          # retention: judicial for a judge; omit for other officials
    title: Shall Justice Pat Example of the Supreme Court be retained in office?   # exactly as printed
    official:
      id: pat-example
      name: Pat Example             # exactly as printed
  - id: question-1
    type: measure
    jurisdiction: XX Exampleton County   # coarser than the township in the printed title
    search_terms: library levy     # measures only: the subject, no place names
    title: "Question 1: Springfield Township Library Levy"   # number and title as printed
    display_title: Question 1     # optional: page title when the printed title would locate the voter; must differ from title
confirmed_supersedes: []  # optional: each corrected sample ballot the researcher confirmed (Corrections)
retired_companions: []    # optional: companion snapshots kept off the read: lines (Companion documents)
```

Text on the ballot that locates or names the voter goes in a separate file, `<election>/<ballot-id>/private.yaml`, so that `ballot.yaml` can be read next to untrusted snapshots (Rule 7). The researcher creates the ballot directory, then this file, before the first `--ballot` (SKILL.md step 2). Only scripts read it, never agents: `ballot-check`, `fetch-snapshot` (for its URL and `source:` name refusals) and `publish`. `fetch-snapshot`, `publish` and `ballot-check` read every ballot's `private.yaml`: `ballot-check` for its `ballot.yaml`, `ignored_lines` and `tiers.yaml` scans (Private text, Tiers):

```yaml
private_strings:
  - Precinct 12         # precinct names and numbers
  - Pat Q. Voter        # voter names printed on a personalized sample ballot
  - Springfield Township   # place names that narrow down the voter's location beyond the contest list
  - BS-0412             # ballot style or split codes, voter ids
  - Lincoln Elementary Gym   # polling place name and address
  - "99999"             # the voter's ZIP code, as its own entry and in quotes
ignored_lines:          # sample-ballot lines that are not contests (instructions, headers, footers)
  - To vote, fill in the oval completely
```

List the voter's ZIP code as its own five-digit entry, and each ZIP on its own when the ballot covers more than one address. Leave out the +4: every run of 4 or more digits in an entry is searched alone, so `99999-0001` would also refuse a bare `0001`. Quote it: YAML reads an unquoted `02134` as the number 2134, and `ballot-check` fails `private-invalid`. As a digit run of 4 or more digits that is not a year, the entry is matched as a standalone token (SKILL.md step 6.3): `99999` is refused in `?zip=99999`, `99999-0001` and `/99999/`, never inside a longer number such as `1999990`, and a refusal reports `private-string`.

No address is stored (ADR 0017), and no script reads `addresses.yaml`. The data repo's settings and session-guard no longer name the file, so nothing but this refusal keeps a leftover one from being read: while one is still at the project root, `ballot-check` fails `addresses-leftover`, located by the file alone and never opening it, so `publish`'s ballot gate, `agent-bind` and `discovery-fetch --brief` refuse too, and SKILL.md step 3 hands the code to the researcher. Its hint, `- list-zips-then-delete`, gives the order: the researcher lists each ZIP the file holds in the `private.yaml` of the ballot it belongs to, as above, then deletes the file.

Contest types: `candidate`, `retention` (one judge or official, yes/no), and `measure`.

Every candidate contest carries an `office_type` from the list in [sections.md](sections.md), which picks its Positions issues; `ballot-check` fails a candidate contest without one or with a value not on that list. A retention contest for a judge carries `office_type: judicial`; other retention contests and measures leave it out.

Any contest may carry `not_researched`, which only the researcher writes: the sections left for later when time is short, each named as in [sections.md](sections.md) without its letter, or `all` for every section apart from On the ballot. `coverage` then requires exactly those sections to be `Not researched yet` ([article-format.md](article-format.md)). `ballot-check` fails a name that is not a section of the contest's type, and On the ballot, which is never left for later. The researcher removes a name once its section is researched.

Candidate contests carry `vote_for`, the number of seats to fill; the page shows "Vote for N" when it is more than 1.

Candidate and retention contests carry `jurisdiction`: the state and the district or court the office covers, so the discovery agent can search the right state databases and local papers without guessing. Measures carry it too, at the level the measure covers (`XX Exampleton County`), plus `search_terms`: a few researcher-written words for the subject (`library levy`), since discovery never sees the title. `ballot-check` applies the same checks to `search_terms` as to `jurisdiction`. It goes into web searches, so it must say no more than the printed contest title already does, and never the locating part of a title that has a `display_title`. `ballot-check` fails a `jurisdiction` or `search_terms` that contains a `private_strings` entry of any ballot in the data repo or the printed `title` of a contest with a `display_title`; use a coarser one (the state, or the state and county).

The page shows `display_title` when it is set and `title` otherwise. The ballot check always uses `title`, and fails when a `display_title` equals its `title`. For a contest with a `display_title`, `check` fails any excerpt that contains the printed `title`, so the problem shows up at compile time, and the publish privacy scan refuses any page that still contains it. `display_title` hides only the full printed title, so also list its locating part (the place name) under `private_strings`; an excerpt that quotes just that part is then refused too. A measure whose official text cannot be quoted without it stays "Not ready yet".

## Ballot check

`ballot-check` compares `ballot.yaml` with the authoritative sample ballot: the `_ballot/` snapshot with `role: sample_ballot` that no later snapshot `supersedes`. Other `_ballot/` snapshots (candidate list, pamphlet, superseded ballots) never satisfy it. Text is compared with the same normalization as excerpts ([article-format.md](article-format.md)), because sample ballots are often PDFs, except that newlines are kept: the snapshot body is split into raw lines first and each line is normalized on its own. A listed title, or a candidate entry (name plus party), may wrap across several lines; every line inside its matched span counts as accounted for.

- **Listed to official:** every contest `title` must appear in the sample ballot, in `ballot.yaml` order: each title is searched for after the previous title's match, so two contests with the same printed title (several "Judge of the Circuit Court" seats) land on their own places, and a title that cannot be placed in order fails. Each candidate `name` must appear as whole words between its own contest's title and the next contest's title, and each retention `official.name` either there or inside its own contest's title, so a name under the wrong contest, or a prefix of a longer printed name ("John Sample" for "John Samples"), fails.
- **Official to listed:** the number of contests must equal `contest_count`. For each `candidate` contest, the printed candidates listed (`on_ballot` plus `withdrawn_still_printed`) must equal `printed_count`. Retention and measure contests have no count. These counts are the researcher's own, so they check `ballot.yaml` against itself. To catch a contest missed in both, `ballot-check` also lists the line number of every sample-ballot line that is not accounted for, never its text, which can be the voter's name or address; the researcher reads the lines with `ballot-check --show` (Rule 5). A line is accounted for only when every letter and digit on it falls inside the matched span of a listed contest title, a contest's `Vote for` phrase, or a listed candidate entry or official name (with its party), when it is made up wholly of `private_strings` entries joined by spaces or punctuation, or when it is an entry in the `ignored_lines:` list in `private.yaml` (instructions, headers, page footers). Only the matched span of a candidate entry counts, so a pdftotext line from a two-column ballot that holds a listed candidate and an unlisted one from the next column stays unaccounted for. Lines made of `private_strings` entries are read as the publish privacy scan reads text in its third form (SKILL.md step 6.3): case folded, each entry a whole phrase, and its separators read as spaces, so an all-capitals header is accounted for by mixed-case entries; punctuation is any character that is not a letter, mark or digit, and entries may overlap. `ignored_lines` lives in `private.yaml` because the leftover lines of a personalized ballot are often next to precinct, voter or polling-place text. It holds only boilerplate; that private text goes under `private_strings`, which the publish scan checks, and `ballot-check` fails an `ignored_lines` entry that contains a `private_strings` entry of any ballot in the data repo. The publish scan matches each entry whole, never a part of one apart from its digit run (SKILL.md step 6.3), so a header line such as "Springfield Township Precinct 12" is accounted for by listing `Springfield Township` and `Precinct 12` as two entries, which also lets the scan catch the township alone; pasting the whole line as one entry would leave its parts unscanned. Since entries may overlap, a header such as "Springfield Township 12", whose `12` alone would match all over the page, is accounted for by listing `Springfield Township` and `Township 12`: the scan then catches the township alone and the number beside its word. When one entry alone accounts for a line that the other entries do not, and it has three or more words and holds a digit run or a place-type word (Township, Precinct, Ward, Borough, Village or City, in any case) before its last word, `ballot-check` warns `private-whole-line`, located by the sample-ballot line and keyed by the entry's number in `private_strings`, counted from 1, never its text: split it into parts the scan can catch alone. A `private_strings` entry equal to a contest title would account for the title line of a contest missing from both the list and the counts, so `ballot-check --show` also lists each line that `private_strings` entries alone account for, with its text. Position on the page never accounts for a line, so a contest left out of both the list and the counts shows up even in the middle of the ballot. The check passes only when the researcher has added each missing contest or copied the line into `ignored_lines`.
- **Ballot view:** on a pass, `ballot-check` writes `<ballot-id>/ballot-view.md`: a `link:` line with the path of the authoritative sample-ballot snapshot, which claims link to and no agent may open; one `read:` line, in path order, per `_ballot` snapshot whose role is `candidate_list`, `pamphlet`, `write_in_list` or `withdrawal_notice`, the only `_ballot` files the compile agent opens and the only ones its allow list takes from this file (never a `role: sample_ballot` snapshot, superseded or not, and never a companion that `retired_companions` lists; session-guard opens one only while this file is a regular file whose `sha256:` lines still agree with `ballot.yaml`, the sample ballot and that companion, SKILL.md Rule 7); then `sha256: <hash>  <path>` lines with the hashes of the `ballot.yaml`, the sample ballot and each companion on a `read:` line, in that order, that it was checked against, so a later gate can refuse a view that any of them no longer agrees with, and the compile agent never opens a companion edited since it was checked; then the matched span of each listed contest title, `Vote for` phrase, candidate entry and retention official name, one per line, in ballot order. This is the only form of the sample ballot the compile agent reads (Rule 7).
- **Companion documents:** `candidate_list`, `pamphlet`, `write_in_list` and `withdrawal_notice` snapshots must be county- or state-wide documents, since the compile agent reads them whole. `ballot-check` fails one whose fetch URL had a query string (`ballot.ledger` records whether it did: `query`). It does not scan a companion's body: with no address stored, what is left to match (a ZIP, title, place name or link) county-wide documents print by nature. A `--file` companion, whose `<query>` is `unknown` since its download's own URL was never seen, therefore passes, and so does a personalized one fetched without a query: spotting it and retiring it is the researcher's. A personalized lookup result is saved only as the sample ballot. A companion that fails, or that the researcher finds personalized, is retired by listing its path (`sources/_ballot/<name>.md`) under `retired_companions:` in `ballot.yaml`, which keeps it off the `read:` lines and out of every check below, so it vouches for no write-in, withdrawal or party name; the researcher then saves a county-wide copy. Each entry must be the path of a companion snapshot the ledger lists, never the sample ballot.
- **Private text:** no `private_strings` entry may appear in `ballot.yaml` outside the printed `title` of a contest that has a `display_title` (that title is copied exactly as printed, and the page never shows it). A county can share a word with a private township (Washington Township in Washington County), so when an entry appears in the `state` or `county` field, `ballot-check` fails, names that field, and says to list the township's full name, never the bare shared word. When a `private_strings` entry equals a field the page shows (a candidate's printed `name`, or `display_name` in `publish.yaml`), `ballot-check` fails and names the field's key, never the text; a name that is public by nature (the voter is on the ballot) comes out of `private_strings`, and the researcher keeps every other entry. When an entry's digit run reads as a year (1900 to 2099, as in a precinct named 2024), `ballot-check` warns, without quoting the entry, that the publish privacy scan matches that run only next to the entry's other words (SKILL.md step 6.3).
- **Party names:** `party` is copied exactly as printed. When the ballot prints an abbreviation, the researcher adds `party_name`, the party's full name as an official `_ballot/` source (the candidate list or the voter pamphlet) spells it out, and the page shows that ([page.md](page.md)). A hyphen joins words, so each part between hyphens is read as a word. `ballot-check` fails, with no `party_name`, a `party` with any word written as an abbreviation: all capitals (`D`, `DEM`, `D-NPL`), holding a period or slash (`Dem.`, `D.F.L.`, `DEM/WF`, `Ind. Am.`), or under 4 letters (`Dem`, `Rep`), apart from the connecting words `and`, `of`, `for`, `the`, `no` and `non` in any case. A full name such as `Green`, `Working Families`, `Democratic-Farmer-Labor`, `Peace and Freedom` or `U.S. Taxpayers` passes, since `U.S.` and `U.S.A.` are read as whole words wherever they appear; a whole short word still counts, so `Natural Law` needs a `party_name`, which may be the same words, and one printed in capitals (`GREEN PARTY`) needs a `party_name`, which may be the same words as an official source writes them. The check that a `_ballot/` snapshot contains it ignores case, except as below. It fails a `party_name` that is itself written as an abbreviation: a word holding a period or slash, or, in a name with a lowercase letter, a word in capitals (`DFL Party`). It also fails a `party_name` that no `_ballot/` snapshot contains (the authoritative sample ballot or a companion that is not retired), so the full name is never the researcher's own guess. When `party_name` is the printed party's own words, the sample ballot vouches for it only when every word of it, connecting words aside, has 4 or more letters: `GREEN PARTY` read as `Green Party`, or `PEACE AND FREEDOM` as `Peace and Freedom`, passes on the sample ballot alone. Otherwise only the case is the researcher's, so a candidate list or pamphlet must spell it in that case: `DEM` read as `Dem` needs a companion that writes `Dem`, and a legend such as `DEM = Democratic` vouches for `Democratic`, never `Dem`.
- **Ids:** every contest, candidate and official `id` matches `^[a-z0-9]+(-[a-z0-9]+)*$`, so an id is always a safe directory name, never collides with `_race` or `_ballot`, and never holds `--`, which page anchors use to join a contest id and a section ([page.md](page.md)). A contest id may not be `ballot`, the page's own anchor for the ballot list. A candidate or official id names one person across the data repo, since a `tiers.yaml` `owner` is a bare id: `ballot-check` fails an id that two `ballot.yaml` files give different printed names, compared after the matching normalization and in any case, since counties print one person's name in their own case (`JANE EXAMPLE`, `Jane Example`), and a different person with the same name gets another id (`john-smith-2`). Contest ids become page anchors, so `ballot-check` fails a contest id that, with hyphens read as spaces, contains a `private_strings` entry or the printed `title` of a contest with a `display_title`.
- **Ballot ids:** the ballot id, the `<ballot-id>` directory name, is exactly `<state>-<county>-<n>`: `state` from `ballot.yaml` in lower case; `county` from `ballot.yaml` with its letters folded to ASCII (ñ reads as n), apostrophes (' or ’) dropped, one trailing City and Borough, Borough, Census Area, Municipality, County or Parish dropped, longest first (never city alone, so St. Louis city and St. Louis County stay apart), lower case, and every other run of spaces or punctuation read as one hyphen; and a 1-2 digit number the researcher picks to tell ballots in one county apart (the example above is `xx-exampleton-1`; Doña Ana County gives nm-dona-ana-1, and Juneau City and Borough gives ak-juneau-1). So it matches `^[a-z]{2}-[a-z]+(-[a-z]+)*-[1-9][0-9]?$` and holds no word the researcher chose. Ending in a number keeps the privacy scan from matching it in ordinary page text. Agents read paths under it, so `ballot-check` also fails a ballot id whose number equals any digit run of any `private_strings` entry: with `Precinct 12` listed, 12 fails, so pick another. The county words are fixed by `ballot.yaml` and already public through the contest list, and the Private text rule already fails a `private_strings` entry in `county`, so the ballot id needs no separate check of them. It checks the ballot directories under every `<election>` directory in the data repo (the Layout gives their pattern), not only the current one, so an id made under an older template is caught. Paths in `ballot.ledger` and `archives.tsv` are relative to the ballot directory, so they never hold the id. To rename a ballot id, the researcher renames its directory, then reruns `ballot-check`.
- **Slug:** `slug` must match `^[a-z0-9]{6}$` and no other `ballot.yaml` in the data repo may use it, so a copied `ballot.yaml` can never publish over another ballot's page.
- **Write-ins:** `certified_write_in` candidates skip the printed-ballot check and must appear verbatim in a `role: write_in_list` snapshot that is not retired: the printed `name`, matched as an excerpt is ([article-format.md](article-format.md), Matching) but in any case, since a county prints one name in its own case (`BO BAKER`, `Bo Baker`). If the county publishes none, the page says "Certified write-ins: none published".
- **Withdrawals:** a `withdrawn_still_printed` candidate must also appear verbatim, matched the same way and in any case, in a `role: withdrawal_notice` snapshot that is not retired, the county or state notice of the withdrawal, so a mistyped status can never hide a candidate's record. A candidate list is not proof, since it names every candidate. Their On the ballot claim cites that snapshot. When the county or state publishes no such notice, the candidate stays `on_ballot` and gets every section.
- **Tiers:** `ballot-check` fails any `tiers.yaml` `match` or `source` that contains, matched as in the publish privacy scan, a `private_strings` entry of any ballot in the data repo, because the discovery agent and its web searches see every `tiers.yaml` host, and every `source` name can reach the page. `fetch-snapshot` runs the same check each time it loads `tiers.yaml`.

Corrections to the sample ballot become a new snapshot with `supersedes` set, plus an edit to `ballot.yaml`. The old snapshot stays. `ballot-check` lists every `supersedes` link and passes only when each one is named in a `confirmed_supersedes:` list the researcher keeps in `ballot.yaml`, so a planted snapshot can never become the authoritative ballot. `supersedes` holds the file name of an earlier `role: sample_ballot` snapshot under `sources/_ballot/`; only a sample ballot carries it, no snapshot supersedes itself or one that another already supersedes, and the links form no loop. Each `confirmed_supersedes` entry is the path of a correcting snapshot (`sources/_ballot/<name>.md`). A sample ballot that a link supersedes is out of every check; the one left, which nothing supersedes, is the authoritative sample ballot.

## Command line

```text
ballot-check <election>/<ballot-id>
```

Once its arguments parse, it checks Rule 8, then checks that the data repo's `.claude/settings.json` holds every deny rule and hook of `data-repo-settings.json` and that git treats `private.yaml` as `-diff`, then looks for a leftover `addresses.yaml` by its name alone, and reads `ballot.yaml`, `private.yaml`, `tiers.yaml`, `ballot.ledger`, `snapshots.sha256`, the `_ballot` snapshots, every other ballot's `ballot.yaml` for the ids and the slug, and every other ballot's `private.yaml` for the Private text and Tiers rules. Like every script, it prints only `location code [key]` lines (Rule 5) and exits non-zero on any failure, reporting every failure it finds rather than the first. Locations are relative to the ballot directory (`ballot.yaml:12`, `sources/_ballot/sample-ballot.md:40`, `ballot.ledger:3`), and the key, when there is one, is the `ballot.yaml` field at fault, never its value. Text the researcher typed is never printed as a key: an unknown key is located by its line alone, and a `private.yaml` failure by the file alone, since a stray key there can be the private text itself. A file under `sources/_ballot/` whose name `fetch-snapshot` could not have given (`^[a-z0-9]+(-[a-z0-9]+)*\.md$`) is located `sources/_ballot/-`, since a dropped file can be named after private text. A failure in another ballot is located `-`, so no other ballot's id reaches the output; the last one is followed by the hint `- check-each-ballot`, since running `ballot-check` on that ballot locates its failures by line. It holds the ballot lock from removing the old view to writing the new one, so a `--ballot` import never saves in between. A pass writes `ballot-view.md` and prints `ballot-view.md written`; any failure after Rule 8 passes removes a `ballot-view.md` left by an earlier pass, so the compile agent never reads one that disagrees with `ballot.yaml`.

Only the researcher, in their own terminal, reads the unaccounted lines' text with `ballot-check --show` (Rule 5), which takes the same argument: it refuses with `not-a-terminal` when stdout or stdin is not a terminal or `CLAUDECODE` is set, before it reads anything; otherwise it runs the same check and prints, under each `line-unaccounted` line, that sample-ballot line's text, indented, with control characters replaced. It also prints a `line-private` line, located by the sample-ballot line and followed by its text the same way, for each line that `private_strings` entries alone account for (Official to listed), whether the check passes or not; the plain command never prints these.

Text is normalized as in [article-format.md](article-format.md) (NFKC, default-ignorable characters removed, curly quotes and dashes folded, whitespace collapsed) one line at a time, and the lines are then joined with single spaces, so a title or entry may wrap. Matching is case-sensitive and on whole words. A candidate entry is the name followed by its `party`, separated only by spaces or punctuation, and any closing bracket right after the party. A line is accounted for when every letter and digit on it falls inside a matched title or entry span. Lines that are empty after normalization need no accounting. `ignored_lines` entries match a whole normalized line. A name run into a longer word by a hyphen or apostrophe (`John Sample` in `John Sample-Jones`) still matches, so the rest of the line is unaccounted for, but a `party` after it is never looked for, so it fails `name-not-found`. The `Vote for` phrase of a candidate contest is the first, between its title and the next title, that reads `Vote for`, in any case (`VOTE FOR ONE`), an optional colon, an optional `not more than`, `no more than` or `up to`, and a count in digits or as a word from one to ten (`Vote for not more than two` reads as 2), and that starts its line or follows the title with only punctuation before it (`(Vote for 1)`, `7th District Vote for one`). A phrase with no count (`Vote for a write-in by writing the name`) is none. Its count must equal `vote_for`; with no such phrase, the contest elects one, so `vote_for` must be 1. The phrase is a matched span, so it needs no `ignored_lines` entry. The Private text rules match as the publish privacy scan does (SKILL.md step 6.3), and their failures name the field and the class, never the matched text. In `ballot.yaml` the whole file is scanned, comments included, for every `private_strings` entry of every ballot in the data repo, except the printed `title` of a contest with a `display_title`; so is each string value as YAML reads it, so a quoted escape (`"Pre\u0063inct 12"`) or a line continuation hides nothing. A match is located by its line, or by its value's first line when only the value as read holds it, and keyed by the field on that line (unkeyed on a comment or an unknown key). A match in `state` or `county` is followed by the hint `- list-full-place-name`. `jurisdiction`, `search_terms` and the contest ids are also scanned for the printed `title` of every contest with a `display_title`. Each `ignored_lines` entry is scanned for the same values as `ballot.yaml`. A `private_strings` entry with no letter or digit left once it is normalized, in any of the scan's variants, would match no text, so it fails. The year warning prints `private.yaml private-year`, and the whole-line warning `<sample-ballot line> private-whole-line <n>`; neither fails the check, and a pass still writes the view.

Codes:

- Rule 8: `guard-no-publish-yaml`, `guard-skill-source-clone`, `guard-skill-source-remote`, `guard-remote-not-private`, `guard-not-git-repo`, `guard-not-repo-root`, as for `fetch-snapshot` ([snapshot-format.md](snapshot-format.md#command-line)).
- Arguments: `usage`, `bad-ballot`, `unknown-ballot`, `not-a-terminal`.
- Data-repo setup ([README.md](../README.md#data-repo-settings)): `settings-outdated` (located `.claude/settings.json`), `private-diff-shown` (located `.gitattributes`).
- The ballot lock: `ballot-locked`, as for `fetch-snapshot`.
- Data files: `file-missing`, `yaml-invalid`, `private-invalid` (`private.yaml` is not a map of lists of strings under `private_strings` and `ignored_lines`, with no other key; an empty file fails too), `addresses-leftover` (an `addresses.yaml` at the project root, located by the file alone; it is never opened), followed by `- list-zips-then-delete`, since each ZIP the file held goes into that ballot's `private.yaml` before the file is deleted.
- Private text, never with the matched text: `private-string` (a `private_strings` entry of any ballot, or its digit run) and `private-title` (the printed `title` of a contest with a `display_title`), located by the `ballot.yaml` line and keyed by field, by `private.yaml` keyed `ignored_lines`, or by the `tiers.yaml` line keyed `match` or `source` (a failure in another ballot's `private.yaml`, read for the Private text and Tiers rules, is located `-`); `private-empty` (an entry with no letter or digit once normalized, located `private.yaml` keyed `private_strings`); `ballot-id-private` (the ballot id's number equals a digit run of a `private_strings` entry, located `private.yaml`); the warning `private-year`, located `private.yaml`; and the warning `private-whole-line`, located by the sample-ballot line and keyed by the entry's number.
- `ballot.yaml`, located by line and keyed by field: `ballot-invalid` (a missing field, a value of the wrong type or outside its list, an unknown key, unkeyed, `party_name` with no `party`, or a YAML anchor or alias, unkeyed, since an alias copies a value, such as a hidden printed title, into a field without spelling it out there), `id-invalid` (an id that is not `^[a-z0-9]+(-[a-z0-9]+)*$`, or the contest id `ballot`), `id-duplicate` (two contests with one id, or two people in one contest), `id-name-conflict` (another `ballot.yaml` gives the id a different `name`, as compared under Ids), `slug-invalid`, `slug-duplicate`, `election-mismatch` (`election` is not the directory's name), `ballot-id-mismatch` (the directory name is not built from `state` and `county` as above, keyed `county`), `display-title-same`, `not-researched-invalid`, `contest-count-mismatch`, `printed-count-mismatch`, `party-abbreviated` (an abbreviated `party` with no `party_name`, keyed `party`), `party-name-abbreviated` and `party-name-not-found` (keyed `party_name`), `write-in-not-found` and `withdrawal-not-found` (keyed `name`). A `retired_companions` entry that is not a ledgered companion's path, or a `confirmed_supersedes` entry that is not the path of a snapshot carrying `supersedes`, is `ballot-invalid`, keyed by its list. Every script reads contests by one set of these rules: `contests` is a list with at least one contest, each a map with a `type` of the three, an `id`, a candidate contest's `office_type` and at least one candidate, a retention contest's `office_type` if it has one, a `not_researched` of the type's sections but On the ballot, each once, or `all`, and each candidate's or the official's `id`, `name` and, for a candidate, `status`. Any other command fails a `ballot.yaml` that breaks one as a whole, `ballot-invalid` located by the file.
- Other ballots, located `-`: `ballot-id-invalid` (a directory under an `<election>` directory whose name is not a ballot id), `ballot-id-mismatch`, `yaml-invalid`, `ballot-invalid`; the last is followed by `- check-each-ballot`.
- The sample ballot: `no-sample-ballot` (no `role: sample_ballot` snapshot), `sample-ballot-not-unique`, `ballot-not-in-ledger` (a file under `sources/_ballot/` with no ledger line, that is not a regular file, or whose name `fetch-snapshot` could not have given, located `sources/_ballot/-`), `ledger-invalid` (a malformed line, or a last line with no newline, located by its line), `ledger-mismatch` (a snapshot whose front matter `role` differs from its ledger line, or has no front matter), `snapshot-hash` (a `_ballot` snapshot's sha256 differs from its line in `snapshots.sha256`, or it has none), `supersedes-invalid` (a `supersedes` that breaks the Corrections rule, located by the snapshot carrying it), `supersedes-unconfirmed` (a link `confirmed_supersedes` does not name, located likewise).
- Companion documents, located by the snapshot: `companion-query` (its `<query>` is `query`).
- Listed to official, located by the `ballot.yaml` line: `title-not-found` (a title missing, or not after the previous one), `name-not-found` (a candidate or official name not under its own contest), `party-not-found` (a name not followed by its `party`), `vote-for-not-found` (no `Vote for` phrase, and `vote_for` is not 1), `vote-for-mismatch`.
- Official to listed: `line-unaccounted`, located by the sample-ballot line; and `line-private`, which only the researcher's `ballot-check --show` (Rule 5) prints and which fails nothing.
- Anything else is a bug: `internal-error`, with the stack on stderr.
